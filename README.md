# chroma-key-reference

A dependency-free chroma key core for JavaScript, plus a reproducible benchmark
and a set of reference tables. Runs in Node and in the browser, works on plain
typed arrays, no canvas and no DOM.

The interesting part is not the keying itself — that is a few dozen lines — but
the fact that the behaviour is **measured** rather than asserted. Every table in
`data/` is regenerated by `node bench/run.mjs` from deterministic fixtures, so
you can check the claims, and diff them when the algorithm changes.

These routines are the ones that run in the browser-based green screen remover
at <https://greenscreenremover.net>; that page is a thin UI around `src/keyer.mjs`.

## What's here

```
src/keyer.mjs             the keyer: colour maths, parameters, pixel loop, autoKey
src/keyer.test.mjs        19 assertions, node:test, no dependencies
bench/fixtures.mjs        six deterministic synthetic frames with ground-truth masks
bench/run.mjs             regenerates everything in data/
docs/algorithm.md         how it works, why, and what the measurements say
data/*.csv                the measurements
```

## Quick start

```js
import { makeParams, keyPixels, autoKey } from './src/keyer.mjs';

// rgba is a Uint8ClampedArray of w*h*4, e.g. from ctx.getImageData(...).data
const key = autoKey(rgba, w, h) ?? [0, 177, 64];
const params = makeParams(key, /* tolerance */ 25, /* edge */ 0, /* spill */ 50);

const out = new Uint8ClampedArray(rgba.length);
keyPixels(rgba, out, params);      // out is RGBA with backdrop alpha = 0
```

`dst` may be the same array as `src`. `keyPixels` returns `dst`.

`makeParams` is separated from the pixel loop on purpose: the parameter object
holds the key colour in Cb/Cr, the two band edges, the spill strength and which
channel dominates. Compute it once per frame, not once per pixel.

## The data

| file | what it is |
|---|---|
| `data/tolerance-sweep.csv` | 126 rows — six fixtures × tolerance 0…100 in steps of 5, scored against ground truth |
| `data/edge-sweep.csv` | 42 rows — the edge control from −100 to +100 on the two fixtures with a spill rim |
| `data/shadow-distance.csv` | how far a shadow moves a pixel in RGB versus in Cb/Cr, at 13 brightness levels |
| `data/auto-key-accuracy.csv` | whether the border-median key detection found the real key colour, and by how much it missed |
| `data/key-presets.csv` | Cb, Cr, luma, chroma magnitude and the resulting band for eight common key colours |

Scoring, in every sweep: a pixel counts as **backdrop** when the keyer gave it
alpha 0, and ground truth comes from the fixture's mask, never from the keyer.

```
precision = tp / (tp + fp)      fp = subject erased by the key
recall    = tp / (tp + fn)      fn = backdrop left behind
iou       = tp / (tp + fp + fn)
```

## What the numbers say

The short version, all of it from `data/tolerance-sweep.csv`:

* Measuring the distance in Cb/Cr instead of RGB roughly **halves** how far a
  shadow moves a pixel (`data/shadow-distance.csv`: 85.09 in RGB versus 37.81
  in Cb/Cr for a backdrop at 55% brightness).
* That is a slowdown, not an exemption. On a fixture with a deep shadow, the
  default tolerance of 25 scores a recall of **0.617718** — 38% of the backdrop
  survives — and the fixture only reaches 1.000 at tolerance 40.
* Raising the tolerance eats a spill rim: on `spill-green`, precision falls
  from 1.000 to **0.885** between tolerance 0 and 80, because the rim is tinted
  with the key colour.
* A frame with both a deep shadow and a spill rim never gets clean — best IoU
  **0.966269**, and it never crosses 0.99. A single global distance threshold
  cannot separate those two cases.
* The neutral (white/black/grey) path is not a gradual trade-off: it holds
  1.000 up to tolerance 50 and collapses to **0.645560** at 60.

`docs/algorithm.md` walks through each of these with the arithmetic behind it.

## Tests

```sh
node --test src/keyer.test.mjs
```

The assertions check properties, not memorised outputs: the exact key colour
keys to alpha 0; a near neighbour survives at tolerance 0 and goes at 100; a
20% shadow keys out at the default tolerance but a 45% one does not; the
feather band produces a real ramp; a neutral key separates two greys of equal
chroma; spill removal moves exactly one channel and only downward; `autoKey`
ignores a subject grazing an edge and returns `null` on a 1×1 frame.

## Regenerating the data

```sh
node bench/run.mjs
```

The fixtures come from a seeded PRNG, so the CSVs are byte-identical across
machines and runs. Nothing in `data/` is copied from anywhere else, which is
the point: change the algorithm, rerun, and read the diff.

## Limits

This is a per-pixel colour decision and nothing more. There is no matte, no
temporal coherence, no brush, no edge-aware refinement, and no attempt to
recover a subject whose colour matches the screen. The benchmark exists in part
to show where that ceiling is, rather than to hide it.
